# Local integration runbook

1. Start Docker, then in this database repo run `npx supabase start` and `npx supabase db reset` (CLI 3.0.0 was used to create the migration). Do not link this project to a hosted Supabase project. Check `npx supabase status` for the local API URL and publishable key. The migration enables RLS and a private `radiographs` bucket. It was applied and locally verified on 9 November 2026. For the same focused service set used here, run `npx supabase start --exclude realtime,imgproxy,mailpit,postgres-meta,studio,edge-runtime,logflare,vector,supavisor`.
2. For a self-contained synthetic check, run `node scripts/local-access-smoke.mjs` in the database repo; it creates local test identities and records, checks RLS/Storage/review/governance, and prints only a pass summary. For a manual matrix, create two local Auth test users, two institutions, memberships and patient grants using a restricted administrative path. Keep credentials outside Git. Case A must be accessible only to user A; case B only to user B. The patient creator receives a grant through a migration trigger. Use institution UUID/study UUID/image UUID as the three private object path components.
3. Copy `research-config.example.json` to ignored `research-config.json` in **each** repo. Set the same local URL and publishable key. Run `npm run dev` in each repo on ports 4173 and 4174. Both can sign in, read only RLS-authorised studies and fetch private image blobs with the user token. The apps are independent installs; demo browser stores are separate across ports.
4. Set the variables listed in `scripts/access-matrix.mjs` in your local shell and run `node scripts/access-matrix.mjs`. It checks authorised and cross-case study reads, private Storage denial, anonymous study listing and attempted role escalation. Also test allowed upload, review role transition, malformed object paths and export denial before enabling writes in research mode. Do not infer policy correctness from UI visibility.
5. A protected analysis worker is **not** connected. Add one only after it validates the Auth token, patient access, study version/hash, scope, preprocessing and approved artifact before every job step and result read. Keep service credentials server-side. No research-mode mock fallback is allowed.

Source and policy reference: [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [Storage access control](https://supabase.com/docs/guides/storage/security/access-control), [private buckets](https://supabase.com/docs/guides/storage/buckets/fundamentals). These were refreshed on 9 November 2026.
